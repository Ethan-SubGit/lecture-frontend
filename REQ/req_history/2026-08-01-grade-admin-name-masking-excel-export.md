## 해석한 의도

두 개의 독립된 요구가 한 문장에 들어 있다.

**(A) 학생 이름 마스킹**
- "보안을 위해서" — 목적이 명시되어 있다. 다만 어떤 위협을 막으려는 것인지는 말하지 않았다. 로그인한 담당자는 어차피 API로 실명을 받으므로, **이 마스킹이 실제로 막을 수 있는 것은 어깨너머 훔쳐보기(화면 공유·캡처·자리를 비운 화면)뿐**이다. 이 한계를 스펙 「2.2 (가)」에 명시적으로 못 박았다.
- "이름 중 한 글자를" — 가리는 글자 수가 **정확히 1개**로 지정되었다. 따라서 4글자 이상 이름에 `남궁**`처럼 2글자를 가리는 한국어 관례를 적용하지 않는다.
- "성적과 관련된 모든 페이지" — **"성적 데이터에서 파생된 학생 이름이 화면에 렌더되는 모든 지점"** 으로 해석했다. 코드 전수 조사로 목록을 확정했다(아래 「확정된 결정 사항」).

**(B) 엑셀 다운로드**
- "성적조회 목록에서" — 위치가 `/scores`로 특정되었다. 새 라우트를 만들지 않는다.
- "전체 목록" — 가장 모호한 단어였다. 세 가지로 읽힐 수 있어(현재 조건의 전 페이지 / 강의 전체 / 무조건 전체) 판단이 필요했다.
- "버튼과 기능" — UI와 동작을 모두 만들라는 뜻. 서버에 다운로드 엔드포인트가 없으므로 **클라이언트가 전체를 받아 파일을 조립**해야 한다.

## 확인한 질문과 답변

작업 착수 전에 **답에 따라 결과물이 달라지는** 두 가지만 확인했고, 둘 다 사용자가 명시적으로 선택했다.

**Q1. 다운로드한 엑셀 파일 안의 이름도 마스킹할 것인가?**
→ **A. 마스킹하지 않는다. 실명 그대로 넣는다.**
- 근거(사용자 의도): 담당자는 성적 대장을 학사 처리·통보 등 실무에 써야 하고, 마스킹된 명단은 그 용도로 쓸 수 없다.
- **이 답이 만들어내는 결과를 스펙에 정직하게 기록했다** — 화면 마스킹은 다운로드 버튼 한 번으로 우회된다. 즉 마스킹은 권한 통제가 아니며, "개인정보 보호 조치를 완료했다"는 근거로 쓸 수 없다. (스펙 「2.2 (가)」, 가정 32·33)

**Q2. 엑셀 형식은 CSV로 충분한가, 진짜 `.xlsx`여야 하는가?**
→ **A. 진짜 `.xlsx`.**
- 결과: `.xlsx`는 ZIP 컨테이너 + 다중 XML 파트(OOXML)라 자체 구현이 비합리적이다. **외부 라이브러리 도입이 불가피**해졌다.

**추가로 확인된 라이브러리 선정 근거 (메인 세션이 `npm audit`으로 직접 확인):**

| 후보 | 취약점 | 유지보수 | 판정 |
|---|---|---|---|
| `xlsx` (SheetJS npm판) | **high 1건** — Prototype Pollution CVE-2023-30533 + ReDoS. npm 버전 `0.18.5`에 방치, 패치 경로 없음 | 중단 | 탈락 |
| `exceljs` | moderate 2건 | 2024년 이후 갱신 없음 | 탈락 |
| **`write-excel-file@4.1.1`** | **0건** | 2026-06 갱신 | **채택** |

**관례 있는 항목은 묻지 않고 가정으로 기록하고 진행했다** — 마스킹 위치(가운데 글자), 파일명 규칙, 컬럼 순서(화면 표와 동일), 대용량 임계값 등.

## 확정된 결정 사항

### 1. 마스킹 규칙 (스펙 「5.6」)

- `lib/format.ts`에 `maskStudentName(name: string | null | undefined): string` 추가. **새 파일을 만들지 않는다** — 이 파일이 이미 표시용 순수 함수의 단일 위치다.
- **렌더 직전 표시 변환**이다. API 타입·응답·검색·정렬·엑셀에는 적용하지 않는다.
- **항상 두 번째 글자(index 1) 하나만 `*` 1개로 치환.** 글자 수는 코드 포인트 단위로 센다(상용구 밖 한자가 반 토막 나는 것을 막는다).

| 입력 | 출력 | 비고 |
|---|---|---|
| `홍길동` | `홍*동` | 기본 |
| `김철` | `김*` | 2글자는 "가운데"가 없어 성을 남긴다 |
| `남궁민수` | `남*민수` | 길이와 무관하게 index 1 고정 |
| `김` | `*` | 1글자도 가린다 — 예외로 두면 그 사람만 완전 노출 |
| `홍 길동` | `홍 *동` | 공백은 마스킹 대상이 아님. 다음 비공백 문자로 이동 |
| `John Smith` | `J*hn Smith` | 영문도 같은 규칙(효과는 낮음 — 가정 41) |
| `  홍길동  ` | `홍*동` | 앞뒤 공백 제거 후 적용 |
| `""` / `"   "` / `null` | `—` | `EMPTY_VALUE_PLACEHOLDER` |

- **4글자 이상에 index 1을 고정한 이유:** 복성(`남궁`) 판별은 성씨 사전 없이는 불가능하고, 위치가 길이에 따라 움직이면 사용자가 어느 글자가 가려졌는지 예측할 수 없다.

### 2. 마스킹 적용 대상 — 코드 전수 조사 결과 (스펙 「2.2 (나)」)

`studentName`을 렌더하는 파일은 아래 **4개가 전부**다.

| 위치 | 지점 | 학번 동반 노출 |
|---|---|---|
| `app/(authed)/scores/page.tsx` | `SCORE_COLUMNS`의 `이름` 컬럼 | 예 (첫 컬럼) |
| `app/(authed)/scores/[id]/page.tsx` | `DescriptionList`의 `이름` 항목 | 예 |
| `components/features/dashboard/StudentRankingSection.tsx` | 표 이름 + `InitialAvatar` + **「최고 평균 평점」 칩 배지** | 표는 예 / **칩은 아니오** |
| `components/features/dashboard/AtRiskStudentsSection.tsx` | 표 이름 + `InitialAvatar` + **「F학점 최다」 칩 배지** | 표는 예 / **칩은 아니오** |

- **`UploadResultPanel.tsx`는 대상 아님** — 실패 행 표의 컬럼이 `row`·`reason` 둘뿐이고 학생 이름을 렌더하지 않는다는 것을 코드로 확인했다.
- **상단바의 로그인 사용자 이름은 대상 아님** — 학생이 아니라 담당자 본인이다.
- **대시보드 두 섹션을 포함시킨 근거:** 성적 데이터에서 파생된 개인 명단이고, 로그인 직후 착지 화면이라 `/scores`보다 노출 위험이 오히려 높다.
- **`InitialAvatar`는 파일을 수정하지 않는다.** 호출부가 마스킹된 이름을 넘기며, 마스킹된 이름의 첫 글자는 원본과 같으므로 표시 결과가 동일하다(1글자 이름일 때만 `*`). 칩을 `*`로 채우면 모든 행이 같은 원이 되어 "행 찾기 앵커"라는 존재 이유가 사라진다.

### 3. 검색과의 불일치 처리 (스펙 「3.9」)

화면에는 `홍*동`, 검색은 `홍길동`으로 해야 하는 불일치를 세 가지로 동시에 완화한다.
1. `학생 이름` 필드 힌트: `"부분 검색"` → `"부분 검색 · 실제 이름으로 입력"`
2. **입력값에 `*`가 있으면 요청을 보내지 않고** 필드 하단 검증 메시지 (그냥 보내면 0건이 오고 사용자는 이유를 알 수 없다)
3. 표 하단 각주 — 마스킹 사실 + "검색·정렬은 실제 이름 기준" 안내(정렬 순서가 어색해 보이는 현상까지 이 문구가 설명한다)

### 4. "전체 목록"의 정의 (스펙 「5.8 (가)」)

**(a) 현재 검색·필터·정렬 조건 그대로, 페이지네이션만 무시** — 채택.

- 근거 1: **사용자가 파일을 검증할 수 있는 유일한 선택지.** 화면의 "전체 N건"과 파일 행 수가 일치한다.
- 근거 2: 검색 조건은 방금 의도적으로 입력한 것이다. 학과를 좁혀 놓고 전 학과가 나오면 배신이다.
- 근거 3: "필터 무관 전체"는 "강의 선택 전에는 조회하지 않는다"는 기존 수용 기준과 충돌한다.
- 정렬 조건도 유지한다.
- **화면이 "무엇을 받는지" 명시할 책임을 진다** — 버튼 옆 보조 문구 *"검색 조건에 맞는 전체 N건"*. 버튼 라벨은 `엑셀 다운로드`로 짧게 둔다(모바일에서 두 줄로 접히지 않게).

### 5. 전체를 받는 방법과 대용량 방침 (스펙 「5.8 (나)(다)」)

- **`pageSize = total`로 1회 재조회.** 화면이 이미 정확한 `total`을 알고 있으므로 추측 pageSize를 보낼 이유가 없다. 페이지 루프는 요청 N배 + 페이지 경계에서 중복/누락 위험이 있다.
- 응답 `total` > 요청 `pageSize`면(다운로드 중 데이터 증가) 파일은 만들되 **잘림을 경고 토스트로 알린다.** 조용히 잘린 파일을 주지 않는다.
- `total > 5000`이면 **확인 모달**(기존 `ConfirmDialog` 재사용). **하드 상한은 두지 않는다** — "전체를 받고 싶다"는 요구를 정면으로 거스른다.
- **퍼센트 진행바를 만들지 않는다.** 단계 2개를 버튼 라벨(`목록 불러오는 중…` → `엑셀 만드는 중…`)과 `aria-live`로 알린다.
- 파일 생성 중 메인 스레드가 멈추는 것(수 초)은 인지하고 감수한다. Web Worker는 범위 밖.

### 6. 버튼 상태 (스펙 「6.2 (나)」)

| 조건 | 버튼 |
|---|---|
| 강의 미선택 | **렌더하지 않음** (빈 상태 문구가 이미 다음 행동을 지시) |
| 로딩·재조회·에러 | 비활성 |
| `total === 0` | **비활성**(감추지 않음 — 검색할 때마다 툴바가 흔들린다) + 사유 문구 |
| `total > 0` | 활성 |
| 다운로드 중 | `loading`(기존 `Button`이 자동 `disabled` + `aria-busy`) |

실패 시: 네트워크/5xx → 에러 토스트 + **화면의 표는 유지**. 401 → 전역 처리(로그인 이동). 파일 생성 실패 → 별도 토스트.

### 7. 파일명 (스펙 「5.7 (다)」)

`성적목록_<강의명>_<학기>_<YYYYMMDD-HHmm>.xlsx` (예: `성적목록_자료구조_2610_20260802-1432.xlsx`)

- **한글 그대로 쓴다** — 서버 `Content-Disposition`이 아니라 브라우저 Blob 저장이라 RFC 5987 인코딩 문제가 없다.
- 금지 문자(`\ / : * ? " < > |` + 제어문자) → `_` 치환, 앞뒤 공백·마침표 제거(Windows), 강의명 50자 상한.
- **결과에 학기가 2개 이상 섞이면 학기 세그먼트를 `여러학기`로 쓴다** — 이 화면은 `lectureName` 부분 일치만 지원하고 `term` 필터가 없어 여러 학기가 섞일 수 있다(기존 가정 10). 파일명이 내용과 다른 말을 하면 안 된다.

### 8. 엑셀 컬럼 (스펙 「5.7 (나)」)

`SCORE_COLUMNS`를 실제로 읽어 화면 표와 1:1로 맞췄다: **학번 / 이름 / 학과 / 학기 / 중간고사 / 중간과제 / 기말고사 / 기말과제 / 합계 / 등급** (10개, 이 순서). 시트명 `성적목록`, 헤더 행 1행.

- **이름 = 실명**(마스킹 없음)
- **학번 = 문자열** (숫자로 쓰면 앞자리 0이 사라지고 지수 표기가 된다)
- **점수 5개 = 숫자 셀** — 화면 일치 원칙의 **유일한 예외**다. 문자열로 넣으면 엑셀에서 합계·정렬·필터가 전부 죽어 파일의 존재 이유가 사라진다. 표시 자릿수는 셀 서식(`0` / `0.0`)으로 맞춘다.
- `null` 값은 빈 셀(화면의 `—`를 넣지 않는다 — 숫자 열이 텍스트 열이 된다)
- **합계 행·소계를 넣지 않는다.**

### 9. 새 컴포넌트를 만들지 않는다 (스펙 「8.2」)

`Button`(loading 내장), `useToast`, `ConfirmDialog`, `Field`, `DataTable`의 `Column.cell`, `fetchStudentScores`, `apiRequest`(401 전역 처리) 모두 이미 있다. 신규는 **`maskStudentName` + 파일명 정제 유틸 + 엑셀 스키마·실행 로직 + 상수 2개 + 의존성 1개**뿐이다.

## 남긴 가정

스펙 「9. 가정」의 **32~46번**이 이 라운드에서 추가된 항목이다. 그중 사용자가 특히 검토해야 할 것:

1. **(가정 33) 화면 마스킹이 엑셀 다운로드로 우회된다.** 사용자가 선택한 결과이며 의도된 트레이드오프다. 다만 이 기능을 "개인정보 보호 조치 완료"의 근거로 대외에 쓸 수 없다. 진짜 통제에는 role 기반 권한 + 서버 측 마스킹 + 다운로드 감사 로그가 필요하고 셋 다 백엔드 변경이다.
2. **(가정 38) 4글자 이상 이름도 index 1을 가린다** — `남궁민수` → `남*민수`. 복성이 반쪽만 가려지는 어색함을 감수한 결정이다.
3. **(가정 42) 5,000건 임계값은 측정값이 아니라 판단값이다.** 실제 데이터 규모·응답 시간·파일 생성 시간을 하나도 측정하지 못했다.
4. **(가정 37) 도메인 기능을 위한 첫 외부 의존성 도입.** 기존 런타임 의존성 3개는 전부 클래스명 조합 유틸이고 아이콘·차트는 자체 구현했다.
5. **(가정 39) 빈 이름을 `—`로 표시한다** — 현재는 빈 칸으로 렌더된다. 미세한 기존 동작 변경이다.
6. **(가정 40) `UploadResultPanel`의 서버 `reason` 문자열에 실제 이름이 담겨 오는지 확인하지 못했다.**

**미결 사항 중 1순위: "학번도 가려야 하는가."** 이번 요청은 이름만 지정했고 학번은 마스킹 후 유일한 식별 수단이라 그대로 두었다. 학번도 가려야 한다면 **동명이인 구분 수단이 사라져 화면 설계를 다시 해야 한다.**
