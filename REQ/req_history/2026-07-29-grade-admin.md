# 2026-07-29 — 대학 성적관리 프론트엔드 (grade-admin)

## 요청 원문

> 백엔드로 만들어놓은 api주소는 http://58.239.220.254:3330/api 에 있어. 이 내용을 참조해서 서비스를 만들어야해.
> 1. 모든 화면은 로그인없이 사용할수 없어. 로그인하지 않았으면 로그인 폐이지로 모두 이동하도록 해.
> 2. 로그인 페이지에서 아이디와 비밀번호를 입력하고 받은 jwt토큰으로 모든 페이지 인증.
> 3. 로그인 후에는 대시보드 화면으로 이동. 대시보드용 API에서 받아온값으로 화면을 구성.
> 4. 메뉴는
> - 수강과목 관리
>  목록, 생성
> - 성적관리
>  성적입력, 수강과목별 성적조회
> 화면이 있어. gnb영역에는 로그인한 사용자 이름과 로그아웃 기능

## 해석한 의도

기존 NestJS 백엔드(Swagger 공개)를 소비하는 학사 담당자용 백오피스를 신규 구축한다. 핵심은 세 가지다.

1. **전면 인증** — 공개 화면은 로그인 하나뿐이고 나머지는 전부 JWT 필요. 미인증 접근은 예외 없이 로그인으로 보낸다.
2. **대시보드 우선** — 로그인 직후 착지점이 대시보드이며, 화면 구성을 `GET /dashboard/summary` 응답 구조에 맞춘다 (임의의 지표를 만들지 않는다).
3. **두 업무 축** — 수강과목(강의) CRUD와 성적(입력·조회). GNB에 사용자 이름과 로그아웃.

"api주소는 .../api" 부분은 실제 엔드포인트 접두어가 아니라 Swagger UI 주소를 가리킨 것으로 해석했다 (아래 검증 참조).

## 확인한 질문과 답변

**Q1. 백엔드 base URL에 `/api` 접두어가 있는가?**
A. 없다. 메인 세션에서 curl로 직접 검증: `GET http://58.239.220.254:3330/health` → 200, `GET http://58.239.220.254:3330/api/health` → 404. `/api`는 Swagger UI 주소다. 실제 base URL은 `http://58.239.220.254:3330` (루트).

**Q2. 개별 성적 등록 API가 없고 엑셀 업로드만 있는데 '성적입력' 화면을 어떻게 만들까?**
A. **엑셀 업로드 화면으로 만든다.** 강의 선택 → 엑셀 파일 업로드 → `UploadExcelResponseDto`의 성공 건수(`createdCount`)와 실패 행(`failedRows`: `row`, `reason`) 결과를 표시한다.

**Q3. 사용자가 지정한 메뉴에 없는 학과(departments)와 학점환산기준(grade-scales)도 범위에 포함할까?**
A. **둘 다 포함한다.** 각각 목록/생성/수정/삭제 화면을 만들고, 메뉴상 어디에 배치할지는 spec-architect가 제안한다.

**Q4. 회원가입 화면을 만드는가?**
A. 만들지 않는다. `POST /users`는 OpenAPI에 `deprecated: true`이고 "사용자 계정은 DB에 직접 등록한다"고 명시되어 있다.

## 확정된 결정 사항

### 범위
- 인증(로그인/가드/로그아웃), 대시보드, 수강과목 CRUD, 성적 엑셀 업로드, 수강과목별 성적조회 + 상세, 학과 CRUD, 학점환산기준 CRUD + 점수→등급 변환 도구.
- 회원가입 화면, 성적 개별 등록·수정·삭제(API 부재), 성적 내보내기(API 부재), 역할 분기(role 필드 부재), i18n은 제외.

### 기술·인증 설계
- Base URL: `http://58.239.220.254:3330` (환경변수 `NEXT_PUBLIC_API_BASE_URL`). **`/api` 붙이지 않음.**
- 토큰 저장: **쿠키 `access_token`** (JS 접근 가능, `Path=/`, `SameSite=Lax`, 세션 쿠키).
  - 근거: Next.js middleware는 서버 실행이라 localStorage를 못 읽는다. Bearer 헤더를 클라이언트가 붙여야 하므로 HttpOnly는 BFF 프록시 없이는 불가능하고, 프록시는 이번 범위 밖. XSS 노출을 인지한 채 채택.
- 가드 2중: (a) `middleware.ts`가 쿠키 존재만 확인해 `/login?next=<경로>`로 리다이렉트, (b) 인증 레이아웃이 `GET /users/me`로 실제 유효성 확인 후 자식 렌더. (a)는 깜빡임 방지, (b)는 만료 토큰 탐지.
- 401 처리: 중앙 fetch 래퍼 단일 지점. 토큰 삭제 → `/login?next=<현재경로>&reason=expired` → 재로그인 후 원래 경로 복귀. **원래 경로 복귀는 지원한다.** `next`는 내부 경로(`/`로 시작, `//` 아님)만 허용해 오픈 리다이렉트 차단.
- 렌더링: App Router는 라우팅·레이아웃·미들웨어용, 데이터는 전부 클라이언트 페칭 (전 API가 Bearer 필요).

### 메뉴 배치 (제안 확정)
사용자 요구 2개 그룹은 그대로 두고, 학과·학점환산기준은 성격이 다른 마스터 데이터이므로 **「기준정보 관리」라는 3번째 그룹으로 분리**했다.

```
대시보드 | 수강과목 관리(목록, 생성) | 성적관리(성적입력, 수강과목별 성적조회) | 기준정보 관리(학과 관리, 학점환산기준 관리)
```

### openapi.json에서 확인해 스펙에 반영한 사실
- 엑셀 업로드 multipart 필드: `file`(binary, 필수), **`lectureName`(강의명 문자열, 필수 — id가 아님)**, `term`(선택, 기본 `2610`).
- 엑셀 컬럼 순서: 학번/이름/학과/중간고사/중간과제/기말고사/기말과제. 합계·등급은 서버 계산.
- 업로드 500은 전량 롤백(존재하지 않는 강의 / 이미 등록된 성적 / 파일 내 학번 중복) → "아무것도 저장되지 않았습니다" 문구로 201 부분 실패와 구분.
- `GET /student-scores` 쿼리: `page`(min 1, 기본 1), `pageSize`(min 1, 기본 20, **상한 없음**), `lectureName`/`studentName`/`departmentName`(부분 검색), `studentNumber`(정확 일치), `sortBy`(enum: studentNumber|studentName|departmentName|totalScore|grade), `order`(enum: ASC|DESC, 기본 ASC).
- **`GET /lectures`, `/departments`, `/grade-scales`에는 쿼리 파라미터가 전혀 없다** → 배열 전체 반환, 검색·정렬·페이지네이션은 클라이언트 처리.
- `GET /student-scores`만 봉투(`data`/`total`/`page`/`totalPages`), 나머지 목록은 배열 직접 반환.
- 삭제는 전부 204(본문 없음) 소프트 삭제.
- `StudentScore.lecture`/`department`는 id가 아니라 객체 전체가 임베드된다.
- `LoginUserDto.name`은 nullable, `User.name`은 non-null → GNB 표시는 `GET /users/me` 기준.

## 남긴 가정

- 토큰 갱신(refresh) 엔드포인트가 없어 만료 시 재로그인이 유일한 경로다.
- 역할·권한 분기 없음 (`User`에 role 필드 부재).
- 엑셀 허용 확장자를 `.xlsx`, `.xls`로 결정 (OpenAPI에 제약 명시 없음). 서버가 `.xls`를 거부하면 `.xlsx` 단독으로 좁힌다.
- 업로드 용량 상한 미상 → 413/500은 공통 에러 문구.
- **성적 조회의 강의 필터가 `lectureName` 부분 일치뿐이다.** `lectureId`도 `term` 필터도 없어 동일 강의명이 여러 학기에 있으면 결과가 섞인다. 완화책으로 결과 표에 학기 컬럼을 필수 노출. 정확한 필터가 필요하면 백엔드 파라미터 추가 요청 필요.
- 학기 코드 검증 규칙을 `YY10|YY11|YY20|YY21` 4자리로 정함 (설명문에서 유도, 서버 강제 여부 미확인).
- 에러 응답 본문을 NestJS 기본형(`{statusCode, message, error}`)으로 가정하고 파싱.
- CORS 허용 여부 미확인 → 막히면 Next.js rewrites/route handler 프록시로 우회.
- 백엔드가 HTTP라 프론트를 HTTPS로 배포하면 mixed content 차단. 로컬 HTTP 전제.
- 소프트 삭제 항목 필터링은 서버 책임으로 가정. 목록에 나오면 클라이언트에서 `deletedAt !== null` 제외.
