## 4. 스펙/디자인에서 벗어난 판단

1. **`summary` 실패 시 확장 8섹션을 감추지 않는다.** spec 3.8은 `totalStudentScores === 0`일 때의 렌더 억제만 규정한다. 초기 구현은 `data ?`로 전체를 감쌌지만, 그러면 summary 1건의 실패가 독립적인 8섹션을 지워 §6.1 격리 원칙이 깨진다. 억제 조건을 `data &amp;&amp; totalStudentScores === 0`으로 좁혔다. 로딩 중에도 8섹션은 자기 스켈레톤을 보인다.
2. **`EmptyState.icon`을 필수로 승격하지 않았다.** design 4.12는 필수라고 했지만 기존 호출부 6곳(목록/검색 결과 빈 상태 등)이 아이콘 없이 호출 중이라 승격하면 전 화면 수정이 동반된다. 이번 라운드 범위(대시보드) 밖 변경이라 선택 유지 + 슬롯만 적용했다.
3. **`상세` 배지를 그룹 B·C 전 섹션이 아니라 3개 섹션에만** 붙였다(학과별 학업성취도·강의별 난이도·학기별 추이). 배지의 목적이 그룹 E의 「…별 요약」과의 위계 표시인데, 학과×강의 교차표와 평가항목별 분석은 대응하는 요약본이 없다(design 4.25·4.26 헤더에도 배지가 없다).
4. **`DashboardFilterQuery`를 `interface`가 아닌 `type` 별칭으로 선언**했다(spec §5.0은 interface). 기존 `FindStudentScoresQuery`와 같은 이유 — interface는 암묵적 인덱스 시그니처가 없어 fetch 래퍼의 `Record` 쿼리 인자에 단언 없이 넘길 수 없다. 필드는 동일하다.
5. **`CardHeader.titleId` prop 추가**(design 4.4.1에 없음). `&lt;section aria-labelledby&gt;`가 카드 제목을 가리키려면 id가 필요해서다.
6. **학과×강의 교차표 스트립 3칩**(집계 강의/비교 학과/집계 성적)을 넣었다. design 4.25에 칩 지정이 없지만 §0.6이 "8개 섹션 전부 스트립"을 요구해, 응답 배열의 단순 집계(개수·합)만으로 구성했다.
7. **`showScrollHint`를 모바일 카드 스택에서 숨겼다** — `/scores`와 업로드 결과 표에도 영향이 가는 변경이지만, 카드 스택 구간에서 "표를 좌우로 스크롤할 수 있습니다"는 사실이 아니다.
8. 알려진 미해결 이슈: design §8.1-5가 지적한 `student-ranking limit` 불일치는 **spec 5.5(=10)를 따랐다**. 화면 문구는 `items.length`에서 만들므로 값이 바뀌어도 어긋나지 않는다.
