# 2026-08-01 — 성적관리 어드민: 네비게이션 구조를 좌측 사이드바로 전환

## 요청 원문

> 기존 스펙 `REQ/grade-admin/spec.md`가 이미 있고, 이를 바탕으로 `ui-ux-designer`와 `frontend-dev`가 실제 코드까지 구현을 마친 상태다(대시보드/강의/성적/학과/학점환산기준 전 화면).
>
> 사용자가 새 요구사항을 줬다: 현재 화면이 너무 단조로워서, 참조 디자인으로 https://github.com/Tailwind-Admin/free-tailwind-admin-dashboard-template (GitHub) 와 라이브 데모 https://next-free.tailwind-admin.com/ 를 참고하라고 했다. 이 템플릿은 **좌측 사이드바 + 상단바** 구조를 쓴다. 사용자에게 "레퍼런스처럼 만들 때 적용 범위를 어디까지 할까요?"라고 물었더니 "전체 앱 셸까지 (사이드바 도입)"을 선택했다 — 즉, 대시보드 카드 스타일뿐 아니라 **전체 앱의 네비게이션 구조를 상단 GNB(가로 메뉴+드롭다운)에서 좌측 사이드바+상단바 구조로 바꾼다.**
>
> 현재 spec.md의 「4.2 GNB / 메뉴 구조」 섹션(대략 213~230번째 줄)은 다음과 같이 **상단 가로 메뉴 + 드롭다운** 구조로 확정되어 있다:
>
> ```
> [로고/서비스명]   대시보드 | 수강과목 관리 ▾ | 성적관리 ▾ | 기준정보 관리 ▾        <사용자이름> [로그아웃]
>
> 수강과목 관리 ▾            성적관리 ▾                     기준정보 관리 ▾
>  ├ 목록      /lectures      ├ 성적입력   /scores/upload    ├ 학과 관리        /departments
>  └ 생성      /lectures/new  └ 수강과목별 성적조회 /scores   └ 학점환산기준 관리 /grade-scales
> ```
>
> 이걸 **좌측 사이드바 + 상단바** 구조로 바꿔야 한다. 사이드바에 위 4개 메뉴(대시보드 단일 링크 + 수강과목 관리/성적관리/기준정보 관리 그룹, 그룹 아래 하위 링크는 펼쳐진 목록 또는 아코디언)를 세로로 배치하고, 상단바에는 사용자 이름 + 로그아웃 정도만 남긴다. 모바일에서는 기존처럼 드로어(햄버거로 토글)를 유지하되, 데스크탑에서는 사이드바가 상시 노출(또는 접기/펼치기 가능)되는 형태로 바뀐다는 점이 핵심 변경이다.
>
> **네 역할은 spec.md를 수정하는 것만이다.** 시각 디자인(색상·그림자·구체적 클래스)은 건드리지 말고, "네비게이션 구조가 상단 가로형에서 좌측 사이드바형으로 바뀐다"는 **구조적 결정**만 spec.md의 「4.2 GNB / 메뉴 구조」 섹션에 반영해라. 필요하면 섹션 제목을 "사이드바 / 메뉴 구조"로 바꾸고, 사이드바 접기(collapse) 여부에 대한 결정(예: 데스크탑은 항상 펼침, 접기 기능은 이번 범위에서 제외하거나 포함 — 네가 판단해 가정으로 남겨도 됨)을 명시해라. 다른 섹션(라우트 표, 데이터 모델, 수용 기준 등)은 이 변경으로 실제 라우트나 API가 바뀌는 게 아니므로 손대지 마라. 단, 「수용 기준」의 GNB 관련 항목(561~564번째 줄 근처, "GNB에 이름 표시", "GNB 메뉴에서 이동 가능")은 사이드바 기준으로 문구만 자연스럽게 다듬어도 된다.
>
> 작업 순서(스펙 규칙): 기존 spec.md를 읽고 해당 섹션만 수정 → `REQ/req_history/`에 이번 변경 이력 파일(`2026-08-01-grade-admin-sidebar-nav.md`)을 추가로 남겨라(형식은 `REQ/README.md` 참고, 요청 원문은 위 사용자 발화를 그대로 인용).

## 해석한 의도

- 화면이 단조롭다는 불만의 해법으로 참조 템플릿(Tailwind Admin)의 **앱 셸 구조**를 채택한다.
- 이번 변경은 **정보 구조(IR)의 재배치**이지 기능 변경이 아니다. 라우트·API·데이터 모델·상태 정의는 그대로다.
- 메뉴 그룹 구성(대시보드 단일 + 3개 그룹, 총 9개 링크) 자체는 유지하고, 배치만 상단 가로형 → 좌측 세로형으로 바꾼다.
- 시각 표현(색·간격·아이콘·애니메이션)은 이 문서의 범위 밖이며 `design.md`가 결정한다.

## 확인한 질문과 답변

| 질문 | 답변 |
|---|---|
| 레퍼런스 디자인 적용 범위를 어디까지 할까요? | **전체 앱 셸까지 (사이드바 도입)** — 대시보드 카드 스타일에 그치지 않고 네비게이션 구조 전체를 교체한다 |

## 확정된 결정 사항

1. **앱 셸을 「좌측 사이드바 + 상단바」 2영역 구조로 전환한다.** 기존 상단 가로 GNB + 드롭다운은 폐기한다.
2. **상단바에는 페이지 이동 링크를 두지 않는다.** 사용자 이름 + 로그아웃(+ 모바일 햄버거)만 담고, 모든 이동 경로는 사이드바로 단일화한다.
3. **그룹은 아코디언으로 동작한다.** 그룹 헤더는 라우트를 갖지 않으며, 클릭 시 하위 링크만 펼침/접힘 토글한다.
4. **초기 상태는 3개 그룹 모두 펼침이다.** 현재 경로가 속한 그룹은 항상 펼쳐져 있고, 펼침/접힘 상태는 저장하지 않아 새로고침 시 기본값으로 복귀한다.
5. **활성 표시는 하위 라우트까지 상속한다.** `/lectures/3/edit`에서도 「수강과목 관리 > 목록」이 활성으로 보인다.
6. **데스크탑(≥1024)에서 사이드바는 항상 펼쳐진 상태로 상시 노출. 아이콘 전용 접기(collapse)는 이번 범위에서 제외한다.**
7. **1024 미만에서는 햄버거 → 오버레이 드로어.** 링크 선택 / 배경 클릭 / `Esc`로 닫힌다. (기존 모바일 동작 유지, 단 기준 브레이크포인트를 768 → 1024로 조정)
8. **라우트 표·데이터 모델·상태 정의·인증 설계는 변경 없음.** 수용 기준은 「GNB」 항목만 「앱 셸(사이드바 + 상단바)」로 대체·확장했다.

## 남긴 가정

- **접기(collapse) 제외 근거:** 접힘 상태 저장 위치(localStorage 등), 아이콘 세트, 툴팁 처리까지 함께 결정해야 하는 별도 범위이며, 메뉴가 9개뿐이라 얻는 이득이 작다고 판단했다. 필요하면 후속 요구사항으로 다룬다.
- **사이드바 노출 브레이크포인트를 `lg`(1024)로 잡았다.** 기존 GNB의 드로어 기준(768)보다 넓다. 사이드바가 가로 폭을 상시 점유하므로 태블릿 세로에서는 콘텐츠 폭 확보를 우선했다. 태블릿에서도 상시 노출을 원하면 `md`(768)로 낮추면 되고, 이 값 변경은 `design.md`에서 흡수 가능하다.
- **그룹 헤더는 이동 불가(라우트 없음)로 가정했다.** 「수강과목 관리」 클릭 시 `/lectures`로 가길 원한다면 별도 확인이 필요하다.
- **로고/서비스명은 사이드바 상단에 둔다고 가정했다.** 상단바 좌측에 두는 안도 가능하나 참조 템플릿을 따랐다.
- **다크모드 토글·검색·알림 등 참조 템플릿 상단바의 부가 요소는 도입하지 않았다.** 현 스펙 범위에 해당 기능이 없다.
- 본문 다른 절(3. 시나리오, 6. 상태 정의, 8. 재사용 자산, 9. 가정)에 남아 있는 "GNB" 표기는 이번 변경에서 손대지 않았고, 4.2 서두에 "GNB = 앱 셸(사이드바 + 상단바)"이라는 읽기 규칙을 명시해 두었다.
